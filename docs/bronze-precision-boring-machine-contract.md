# Bronze Precision Boring Machine — K1 source contract

**Status:** Bronze III source candidate on draft PR #11. Static geometry/source checks
are not Java compilation or in-game verification. Do not merge until verified.

## Purpose and material progression

The machine provides **internal bore finishing** on a stationary bronze
casting, distinct from the existing Mechanical Lathe's external turning,
rough gear finishing and precision bearing production. It deliberately
reuses the Foundry/Casting Basin path rather than introducing a new mold
or ore before the agreed post-multiblock material integration pass.

- Input: **one `magneticraft2:rough_bronze_bearing`** from the existing
  bronze Bearing Green Sand Mold -> Foundry -> Casting Basin loop.
- Output: **one `magneticraft2:bronze_bushing`**, a different component
  from `precision_bronze_bearing`, which the Lathe still produces.
- Time: **200 supplied ticks**, minimum **20 Gear V2 RPM**, **6 torque**.
  All numbers are provisional and data-driven in
  `recipes/bronze_boring_bushing.json`; no phantom or free rotations.
- Tool: installed `abrasive_boring_bit`, initially pristine, **384 successful
  batches** of wear. Flint is an abrasive insert with a bronze holder;
  no Iron/Steel Age dependency is added for this first Bronze machine.
- Downstream use: one Bronze Bushing in an **additive Mechanical Water Pump
  crafting recipe** with 2 planks, 1 wood shaft and 1 small wood pulley.
  The existing six-plank/Copper-Plate/Shaft/Pulley recipe is untouched.
  The bronze part substitutes for more wooden structural material at
  higher manufacturing cost; the resulting pump has the **same** current
  performance. No novel pump block or invented hydraulic upgrade.
- Quality: `taggedOutput` copies the source casting's CompoundTag onto
  the newly machined bushing *before* simulated and actual output
  insertion, preserving the Foundry's existing provenance/ingot grade.
  This is currently a **1:1 item-only** recipe. **Vanilla shaped crafting
  does not propagate that Bushing NBT into the pump**; quality propagation
  in assembled machines belongs to the agreed future cross-ore pass.
  Do not claim end-to-end machine quality until that pass is implemented.

## Exact machine layout (5 wide × 3 high × 3 deep)

Canonical server-side SOUTH blueprint, rows BACK -> FRONT:

```text
Y1 (bottom):
SSISS
USSSO
SSCSS

Y2 (middle):
PAAAP
PAAAP
PAAAP

Y3 (top):
PPPPP
PAAAP
PPPPP
```

`S` Stone Bricks; `P` Oak Planks; `A` required clear AIR.
`I` is the real rear-center Mechanical Input (x=2,z=0).
`U` is the LEFT-side Item Input (x=0,z=1).
`O` is the RIGHT-side Primary Output (x=4,z=1).
`C` is the front-center controller (x=2,z=2). All x/y/z are
zero-based within the 5×3×3 blueprint.

West, North and East layouts and render-air anchors are generated by
exact right-angle rotations of SOUTH. **Patchouli's visual pattern
mirrors SOUTH's X coordinates**, so its displayed Y1 base must read
`SSISS / OSSSU / SS0SS`. The Forge Hammer previously failed
formation because its construction guide copied the unmirrored ports.
The test explicitly checks every row against the actual blueprint.

## Mechanical design and Studio reference

The rear real Mechanical Input sits in the bottom cell with its shaft
center approximately at y=8 model pixels. The static rear gearbox at
z≈-16 is an enclosed, physically supported reduction/transfer housing
that lifts its second rotation axis to the boring tool center at y≈20px.
The 5×3×3 frame uses stone foundation and work bed, oak corner posts,
iron table/guide rails, bronze clamps, and a headstock-supported abrasive
boring bar. Feed direction is local **+Z** towards the stationary casting.
Unlike a Lathe, the **tool rotates and the workpiece is clamped**, with
the internal hole machined along the workpiece's axis.

Two *distinct* cached baked models are drawn by the BER:
1. `bronze_precision_boring_machine_coupling`, from local z=-32..-16
   at y=8, in the invisible-when-formed real Gear V2 module cell.
2. `bronze_precision_boring_machine_spindle`, local z=-16..0 at
   y=20, with counter-rotation from the input through the housed gear pair.
   The end touches the physical front vise; the rough casting is rendered
   stationary with its hole axis facing the tool.

This K1 does NOT visually simulate a continuous advancing boring feed,
chip removal, coolant, lead screw or metalworking tolerances; those
are later Studio/quality improvements. It also does not instantiate
a new Gear V2 node, per-frame block model, item entity or new rendering
system. The one-source static Voxel V2 design is kept at
`tools/multiblock-models/designs/bronze_precision_boring_machine.json`.
Derived source faces, collision and all four block-local model sets
are regenerated by the established pipeline. No geometries are baked
into real I/U/O module cells and every face retains native UV density.

## Inventory, load and maintenance safety

- The controller server ticker MUST match
  `BlockEntityRegistry.BRONZE_PRECISION_BORING_MACHINE_BE`. The exact
  type is asserted, with explicit rejection of copied Forge/Press/Mill
  ticker registrations; a past wrong ticker disabled Forge Hammer processing.
- The real rear Mechanical Input Module supplies the reference Gear V2
  node. Load qualification uses **raw** RPM to avoid overload-induced
  load toggling, but **only** the authoritative
  `GearNetworkManager.getMechanicalLoadState(...).supplied()` permits
  work progress. Stalled or overloaded networks do not consume items.
- The full NBT-tagged output stack is tested through simulated insertion
  before consuming input; identical saved output tags may stack, while
  different material qualities cannot silently merge. Completed output
  is inserted once; every successful batch wears exactly one bit cycle.
- Recipe identity and input identity/NBT changes invalidate partial progress.
  Save inventory and `BoreProgress`, `BoreRecipe`, `BoreActiveInput`,
  `BoreActiveOutput`, `BoreBit` and `BoreRunning` together with the formed multiblock
  structure/voxel NBT. Chunks must not process while unloaded.
- No item capability bypass at the controller: automation uses linked
  real U/O module BEs. Backpressure, no bit or invalid recipes release
  demand. The controller reports observed RPM/torque, upstream load,
  ingredient counts and a concise stall reason on ordinary right-click.
